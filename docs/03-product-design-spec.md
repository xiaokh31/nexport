# 产品与视觉规格

状态：开发前设计方向  
日期：2026-08-13

## 1. 设计命题

具体主题是“为跨境电商卖家提供海外仓储、订单履约和运输衔接的企业官网”。主要受众是正在筛选海外仓服务商的运营负责人、品牌方和物流采购。公开站点的单一首要任务是把“我们如何接货、存储、处理并交付”讲清楚，并把访客带入有效询价。

视觉方向定为“海外仓作业控制面板”，但它仍是可信、易读的企业官网，而不是伪装成软件仪表盘。所有结构符号都来自真实仓库语汇：装卸口、货位、托盘标签、作业路径、状态标识和交接单。

## 2. 信息架构

```text
公开网站
├── /                         首页：定位、流程、方案、能力、新闻、询价 CTA
├── /solutions               按业务目的分组的解决方案
│   └── /solutions/[slug]    适用对象、范围、流程、所需资料、FAQ、询价
├── /news                    可抓取的文章列表与分页
│   └── /news/[slug]         服务端渲染的文章详情
├── /about                   公司展示结构；事实内容待确认
├── /contact                 公司联系占位 + 核心询价表单
├── /privacy                 固定页面 CMS
├── /terms                   固定页面 CMS
├── /login
└── /register

用户区域 /user
├── /                        真实询价与通知概览
├── /quotes                  当前用户的询价/报价
├── /notifications           站内通知
├── /profile
├── /password
└── /settings                已实现的通知与语言偏好

管理区域 /admin
├── /                        管理员概览
├── /quotes                  报价处理
├── /articles                文章列表、创建、编辑、发布
├── /users                   用户、角色、文章权限
├── /messages                建议重命名为通知管理，仅管理员广播
├── /pages                   隐私政策/条款等固定页面
└── /settings                系统配置
```

新项目不承接旧 `/services/**` URL 时删除兼容层，所有站内入口直接使用 `/solutions`。

## 3. 首页规格

首页不再沿用“Hero + 四个假数字 + 同质卡片”的模板顺序。建议模块如下：

1. **Hero：仓储履约主张**
   - 一句话回答服务对象、主要能力和下一步动作。
   - 主按钮“获取询价”，次按钮“查看解决方案”。
   - 公司名称保持占位；不写仓库面积、时效、客户数等未经确认事实。
   - 视觉主体是装卸口框架与真实作业流程，不使用无意义渐变。
2. **作业流程轨道**
   - 只用真实顺序编号：入库接收 → 上架存储 → 拣货/增值处理 → 出库交接。
   - 每一步说明客户交付什么、站点执行什么、产生什么结果。
3. **按目的分组的方案**
   - 仓储履约：`warehouse`、`dropshipping`、`returns`。
   - FBA 准备与交付：`amazonFba`、`fbaLastMile`。
   - 运输衔接：`truckFreight`、`crossBorder`、`express`。
   - 每张入口可点击，并有一致的焦点、悬停和触摸状态。
4. **可验证的运营能力**
   - 公司数据未确认时用能力清单、流程照片或服务范围说明，不显示固定 `0` 或虚构大数字。
5. **适用客户/合作方式**
   - 用具体场景说明适合品牌方、平台卖家或物流伙伴，不写空泛“全球领先”。
6. **最新行业洞察**
   - 展示最新三篇已发布文章，形成首页到新闻及方案的内部链接。
7. **询价 CTA**
   - 告知提交前需准备的信息，按钮进入表单而非泛化“联系我们”。

## 4. 解决方案规格

### 4.1 总览页

- 先按业务目的分组，再展示具体方案，避免八张同权重卡片造成选择困难。
- 每个方案显示标题、适用场景、三项核心能力和明确详情入口。
- 不展示承运商 Logo 或合作关系暗示，除非公司提供授权和事实确认。
- 删除 `chinaToCanada` 后，导航、页面、询价选项和 sitemap 不得出现该项。

### 4.2 详情页统一结构

1. 服务名称与一句话边界。
2. 适用客户与典型需求。
3. 服务范围和明确不包含的事项。
4. 按真实顺序呈现的操作流程。
5. 客户询价前需准备的资料。
6. 常见问题；没有真实答案时不填充假内容。
7. 相关行业文章。
8. 带当前 `serviceType` 预选的询价入口，例如 `/contact?service=WAREHOUSE`。

`amazonFba` 表述为 FBA 前置处理，`fbaLastMile` 表述为预约/送仓/尾程，避免重复。`warehouse` 表述为仓储与履约服务，不宣传本项目提供 WMS 软件。

## 5. 询价体验规格

### 5.1 字段

MVP 必填：姓名、邮箱、电话、服务类型、需求说明。  
条件或选填：公司、起运地、目的地、货物类型、件数/箱数/托盘数、重量及单位、尺寸及单位、期望时间。

字段必须使用结构化单位或在标签中明确单位，不能让后台猜测 `weight`、`dimensions` 的含义。不同服务可显示针对性提示，但必须共享同一服务枚举。

### 5.2 状态

- 初始：说明预计需要哪些资料。
- 校验失败：字段级错误关联到控件，首个错误可聚焦。
- 人机验证失败：说明重新验证或稍后重试，不显示内部 provider 信息。
- 提交中：防重复提交，按钮文案保持“正在提交询价”。
- 成功：返回可引用的询价编号；登录用户可直接进入“我的询价”。
- 服务端失败：显示可恢复提示并保留已填数据，不能只写 `console.error`。

所有状态用 `aria-live` 宣告。由方案详情进入时预选服务，用户仍可修改。

### 5.3 数据与隐私

- 访客记录不自动归属任何同邮箱账户。
- 用户中心只按 session `userId` 查询。
- 表单包含对隐私政策的清晰引用；具体法律措辞由公司和法律顾问确认。
- 公共表单执行服务端 CAPTCHA、合理的速率限制与输入长度限制。

## 6. 新闻与内容规格

### 6.1 编辑字段

- 标题
- 稳定且唯一的 slug
- 手写摘要
- 正文
- 分类与标签
- 封面图与 alt 文本
- SEO 标题与描述（可从标题/摘要安全回退）
- 作者标识与展示名快照
- 草稿/发布/归档状态
- 首次发布时间和更新时间

首次发布后标题变化不能自动重写 slug。slug 修改属于明确的高级操作，并应考虑重定向。

### 6.2 公开输出

- 新闻列表、分页和详情均在服务端输出可读 HTML。
- 只有 `PUBLISHED` 文章可公开访问。
- 每篇文章生成 title、description、canonical、Open Graph、Article JSON-LD。
- sitemap 使用真实 `publishedAt`/`updatedAt`，不把每次构建时间伪装成所有页面更新时间。
- 正文使用 Markdown 存储并由共享服务端渲染器输出，原始 HTML 默认禁用；图片、表格、代码、长链接在移动端不能溢出。
- 文章页关联相关方案和相关文章，首页展示最新文章，建立内部链接。
- 公司信息未确认前，不输出占位作者组织或 LocalBusiness 实体。

### 6.3 语言与 SEO

当前语言切换由客户端 localStorage 管理，没有 `/zh`、`/en`、`/fr` 页面。MVP 先删除虚假的 hreflang，仅对真实 URL 输出 canonical。若后续需要多语言搜索收录，应改造成真正的 locale 路由和按语言区分的内容模型，不能只切换客户端文本。

## 7. 账户与后台体验

- 登录、注册、用户中心和后台采用同一设计 token，但公开营销页与工作台密度可以不同。
- 删除演示账户提示、伪 2FA 和无功能的头像上传。
- 用户首页只显示真实的询价状态、最近通知和资料入口。
- 后台导航只显示当前能力允许的模块；无权访问返回明确 403 或安全跳转，不能无限加载。
- 表格在窄屏使用优先字段、可展开详情或横向容器，不把所有列压缩到不可读。
- 角色变更、删除、发布、广播等高影响操作需要确认和清晰结果反馈。

## 8. 视觉系统

### 8.1 色彩 token

| 名称 | 色值 | 用途 |
|---|---|---|
| Dock Navy | `#102632` | 主文字、Header、深色作业框架 |
| Steel Blue | `#375566` | 次级文字、图标、信息层级 |
| Concrete | `#EDF0EC` | 页面底色和轻分区 |
| Signal Amber | `#F2A900` | 主 CTA、焦点和关键作业节点，禁止大面积滥用 |
| Pallet Kraft | `#B88958` | 材质感小面积辅助、标签边线 |
| Paper White | `#FAFBF8` | 内容面和表单背景 |

错误、成功、警告另设语义色，必须同时配合图标或文字，不能仅依赖颜色。最终 CSS token 同时覆盖前台、用户中心和后台 primitives。

### 8.2 字体

- 展示标题：`Barlow Condensed`，用于英文/法文大标题和短标签，克制使用。
- 中文与正文：`Noto Sans SC`/`Noto Sans` 加系统回退，保证长文可读。
- 货位、流程、编号和数据：`IBM Plex Mono`。

字体应自托管或采用不会让生产构建依赖外部下载的方案，并在加载失败时保持版式稳定。中文正文不能被强制套用不支持 CJK 的窄体字体。

### 8.3 布局与标志性元素

标志性元素是“装卸口/货位坐标轨道”：Hero 主视觉像一个打开的 loading bay，边缘刻度只标注真实的作业阶段或方案分组；方案与流程用货位标签的对齐逻辑组织。这个风险点让页面与仓储主题建立直接关系，但不把每个组件都做成标签或仪表。

### 8.4 自我校验

这套方向刻意移除当前通用的黑白 shadcn token、渐变 Hero、同尺寸圆角卡片和无依据的大数字。Signal Amber 来自仓库安全标识，装卸口框架来自真实场景，而不是任意的“科技蓝”。为避免沦为装饰，坐标、编号和状态只能在表达真实流程或分类时使用；其余区域保持安静、精确的排版。

## 9. 动效

- 只安排一个编排完整的动效：首次进入时，作业轨道从入库依次推进到出库。
- 其余交互使用短促的焦点、悬停和展开过渡，不做四处漂浮的卡片动画。
- `prefers-reduced-motion: reduce` 下直接显示最终静态状态。
- 动效不得推迟首屏内容、阻碍表单或改变阅读顺序。

## 10. 图片与素材规范

- 优先使用公司提供并确认授权的真实仓库外观、货架、收货、拣配、包装和交接照片。
- 素材未提供前使用明确占位，不用竞品 Logo、承运商商标拼图或不相关的 AWS 标识。
- 不依赖图片内嵌中文传递信息；多语言文字由 HTML 输出。
- 每张信息图片提供准确 alt；纯装饰图使用空 alt。
- 建立统一裁切比例、亮度和色彩处理，不混合卡通、照片和透明抠图。
- 封面图来源与授权需要可追溯。

## 11. 响应式与无障碍验收

- 验证 320、375、768、1024、1440、1920 宽度，无横向滚动。
- 768–1024 单独检查 Header；只保留一个语言切换器，移动菜单有可访问标题。
- 提供“跳到主内容”链接、唯一 H1、连续标题层级和可见键盘焦点。
- 导航、语言切换、筛选、询价和文章后台可全程键盘操作。
- 正文与控件达到 WCAG AA 对比度目标；交互触点至少约 44×44px。
- 新闻筛选使用 `aria-pressed` 或标签页语义；表单错误与字段关联。
- 支持 200% 缩放；法文长词、邮箱、URL、表格和文章图片不能截断或溢出。
- 状态不只靠颜色，加载动画对读屏提供文本，空状态给出下一步动作。

## 12. 内容写作规则

- 从客户可控制和识别的事项出发，例如“提交货物尺寸”，而不是“触发 Quote API”。
- 用具体动词：“提交询价”“发布文章”“保存设置”，成功反馈保持同一词汇。
- 不写“领先、专业、全球、极速”等无法证明的空泛形容词。
- 错误说明发生了什么以及用户如何修复，不道歉、不暴露内部堆栈。
- 公司事实未确认时，宁可隐藏模块或显示配置待完成，也不编造内容。

### 12.1 公司信息未确认时的页面规则

- Hero 可使用已经由本项目范围确认的中性主张：“海外仓储、订单履约与运输衔接”；不附加地点、规模、时效或排名。
- 解决方案可使用本规格第 3–4 节的服务名称和通用流程，不写覆盖城市、处理能力、SLA 或平台认证。
- About 只实现版式骨架；开发/预览环境显示“公司信息待配置”，生产配置不完整时隐藏事实模块并阻止发布。
- Contact 隐藏仍为 `example.com`、`555`、`Address to be configured` 的字段，不能把占位值展示为真实联系方式。
- 统计、客户案例、团队、证书、合作伙伴和仓库照片模块在真实资料到位前完全隐藏。
- Organization、LocalBusiness、作者组织和 partner 结构化数据在身份配置完整前不输出。
