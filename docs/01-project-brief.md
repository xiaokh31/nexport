# 项目简报与范围

状态：开发前基线  
日期：2026-08-13  
面向读者：产品负责人、设计 Agent、开发 Agent、验收人员

## 1. 产品定义

将现有跨境物流项目重构为一家尚未定名公司的海外仓储与履约企业官网。网站同时承担四项职责：建立业务可信度、获取有效询价、为客户提供报价与通知自助入口、通过持续发布行业内容获得自然搜索流量。

首页的单一核心任务是：让跨境电商卖家或物流需求方快速理解仓储履约能力，并提交信息完整的询价。

## 2. 目标结果

- 形成与旧项目明显不同、符合海外仓作业场景的视觉与信息结构。
- 访客可从首页和任一解决方案详情进入可用的询价流程。
- 登录用户只能查看与自己账户明确关联的询价、报价和通知。
- 授权员工可按统一权限规则处理报价或文章，服务端与菜单权限一致。
- 已发布文章可由搜索引擎直接抓取正文、元数据、结构化数据和站点地图 URL。
- 删除不属于企业官网的扫码对账，以及演示或伪安全功能。
- 在依赖清理后通过安装、Prisma 校验、lint、类型检查和生产构建。

## 3. 主要用户

| 用户 | 主要目的 | 必须完成的动作 |
|---|---|---|
| 潜在客户 | 判断服务是否匹配并获得报价 | 浏览方案、准备询价资料、提交询价 |
| 已注册客户/合作伙伴 | 跟踪已提交的询价 | 登录、查看报价状态、读取通知、维护资料 |
| 运营员工 | 处理销售线索和报价 | 筛选询价、填写金额与备注、更新状态 |
| 内容编辑 | 发布能被搜索收录的内容 | 创建草稿、预览、发布、更新文章 |
| 管理员 | 管理站点与权限 | 管理用户角色、文章权限、页面、通知和系统配置 |

## 5. 解决方案基线

删除 `chinaToCanada` 后暂时保留以下八项。正式文案需在公司业务确认后再写，但技术枚举先稳定，禁止继续用 `key.toUpperCase()` 推导。

| 配置 key | 建议稳定值 | 暂定业务边界 |
|---|---|---|
| `fbaLastMile` | `FBA_LAST_MILE` | FBA 预约、送仓与尾程交付 |
| `truckFreight` | `TRUCK_FREIGHT` | 卡车、零担或整车运输 |
| `crossBorder` | `CROSS_BORDER` | 跨境干线与转运协同 |
| `amazonFba` | `AMAZON_FBA` | FBA 前置处理、贴标和入仓准备 |
| `express` | `EXPRESS` | 快递/加急服务；现有“加拿大至中国”语义待确认 |
| `warehouse` | `WAREHOUSE` | 海外仓储、库存处理和订单履约，不表述为售卖 WMS 软件 |
| `dropshipping` | `DROPSHIPPING` | 一件代发、拣货、包装和出库 |
| `returns` | `RETURNS` | 退货接收、质检、换标和再上架 |
| 无固定方案 | `OTHER` | 其他有效询价 |

`amazonFba` 与 `fbaLastMile` 的内容边界、`express` 的方向性必须在正式内容生产前确认；技术实现不得自行合并或编造运输覆盖范围。

## 6. 核心业务流程

### 6.1 询价到报价

1. 访客从首页、方案详情或 `/contact` 进入询价。
2. 从方案详情进入时预选对应 `serviceType`，仍允许修改。
3. 服务端验证字段、人机验证和请求频率后创建询价。
4. 未登录询价保持匿名，不按邮箱自动挂到任何现有用户。
5. 登录用户提交时只使用当前 session 的 `userId` 建立归属。
6. 授权员工查看并更新状态、金额和内部/客户可见备注。
7. 状态发生有效变化时只创建一次通知；用户在用户中心查看。
8. 历史匿名询价如需认领，必须通过已验证邮箱或一次性认领流程，MVP 不自动认领。

### 6.2 文章发布

1. 管理员或 `STAFF + canManageArticles` 创建草稿。
2. 服务端验证标题、稳定 slug、摘要、分类、标签和正文，并净化可发布内容。
3. 编辑者预览与公开页面采用相同渲染规则。
4. 首次发布写入 `publishedAt`；后续编辑不重置首次发布时间。
5. 发布后文章出现在新闻列表、文章详情、站点地图和 Article JSON-LD 中。
6. 取消发布或归档后，公开 API、页面和站点地图均不可继续返回该文章。

### 6.3 账户与通知

1. 注册、凭证登录均经过服务端 CAPTCHA；缺少密钥或验证服务异常时 fail closed。
2. 用户中心只展示项目真实支持的询价与通知，不展示虚构订单、库存或固定数字。
3. 报价状态通知是首个必须闭环的自动通知来源。
4. 有账户归属的报价状态站内通知始终保留；匿名询价不产生面向询价者的站内或状态邮件。`emailNotifications` 是邮件总开关，`quoteEmailUpdates` 是报价邮件类别开关；邮箱验证等必要事务邮件不受这两个偏好影响。MVP 删除没有事件来源的 `newsUpdates`，尚未实现的开关不显示。

## 7. 建议权限基线

服务端能力而非角色名称决定权限。以下是 MVP 的最小权限建议，开发前若无新业务决定即按此执行。

| 能力 | ADMIN | STAFF | FINANCE | WAREHOUSE | CUSTOMER/PARTNER |
|---|---:|---:|---:|---:|---:|
| 后台概览 | 是 | 否 | 否 | 否 | 否 |
| 查看/处理询价 | 是 | 是 | 是 | 否 | 仅自己的只读 |
| 管理文章 | 是 | 仅 `canManageArticles=true` | 否 | 否 | 否 |
| 管理用户与角色 | 是 | 否 | 否 | 否 | 否 |
| 管理固定页面/设置 | 是 | 否 | 否 | 否 | 否 |
| 广播通知 | 是 | 否 | 否 | 否 | 否 |
| 用户中心 | 是 | 是 | 是 | 是 | 是 |

报价状态机固定为 `PENDING → PROCESSING → QUOTED → ACCEPTED/REJECTED → CLOSED`。允许的前进、回退、直接关闭及字段编辑范围以[技术执行计划 3.3 节](./04-technical-execution-plan.md#33-quote)的两张矩阵为唯一契约；矩阵外转换一律拒绝。FINANCE 的“报价备注”明确指客户可见报价备注，不含内部备注；`CLOSED` 是不可重开的终态。CUSTOMER/PARTNER 在 MVP 只读。扫码删除后，`WAREHOUSE` 不进入管理后台，但角色保留供未来仓储业务系统使用。

## 8. 非目标

- 不建设 WMS、扫码、入库、库存、订单履约执行或物流跟踪系统。
- 不在本阶段实现真实 2FA、恢复码或设备信任。
- 不接入 Sanity、Contentful 或其他第三方 CMS。
- 不编写未确认的公司简介、地址、团队、仓库能力、业绩数字、客户案例或合作伙伴声明。
- 不以静态假数据模拟订单、库存、客户数或仓库面积。
- 不在规划阶段安装依赖、运行迁移、启动服务或修改业务代码。

## 9. 项目约束

- 许可证固定为 AGPL-3.0，`LICENSE` 不修改。
- 项目是新基线且无生产数据时，最终 schema 直接合并到单一 `prisma/migrations/0_init/migration.sql`；若未来出现共享数据库，必须停止重写基线并改用增量 migration。
- 页面继续支持现有中文、英文、法文 UI，是否建设真实语言 URL 需单独决定；在此之前不得声明不存在的 hreflang URL。
- 所有外部服务均需明确环境变量、缺失时的行为和部署检查，不允许“缺配置即成功”。
- 未确认授权前，不展示承运商 Logo 或暗示合作关系。

## 10. 待确认但不阻塞基础开发的事项

| 决策 | 默认处理 |
|---|---|
| 公司身份与实际联系资料 | 继续使用中性占位，结构化实体标记暂不输出 |
| 站点主语言和真实语言 URL | 保留三语 UI；先移除虚假 hreflang，语言路由另立任务 |
| CAPTCHA 提供商 | 沿用 reCAPTCHA v2 作为默认方案，统一服务端验证；可在开发前改选同等服务 |
| 匿名询价认领 | MVP 不自动认领；未来仅允许验证邮箱后认领 |
| 普通联系留言 | 默认删除重复链路，由询价表单承接业务联系 |
| `FINANCE` 的状态编辑范围 | 按第 7 节执行：金额、币种、报价备注，以及 `PROCESSING → QUOTED` |
| 图片托管与上传 | MVP 仅接受受控来源；对象存储和上传流程另行决定 |

## 11. 完成定义

项目初期重构只有在以下条件同时满足时才算完成：删除项无任何路由/API/schema/依赖残留；保留功能完成端到端冒烟；权限在服务端生效；文章可抓取；公司占位不被当作真实实体输出；`pnpm install` 后 Prisma generate、lint、typecheck 和 build 全部通过；AGPL-3.0 仍存在。
