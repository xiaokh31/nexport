# 规划文档导航

状态：初期规划完成，尚未进入开发  
基线日期：2026-08-13

这些文档把现有项目整理成可由开发 Agent 逐项执行的工作包。它们记录的是目标状态和实施约束，不表示代码已经完成对应改造。

## 阅读顺序

1. [项目简报与范围](01-project-brief.md)：产品目标、保留/删除边界、角色与关键决策。
2. [当前状态审计](02-current-state-audit.md)：现有代码地图、已确认故障、删除面和卫生问题。
3. [产品与视觉规格](03-product-design-spec.md)：信息架构、页面职责、海外仓视觉方向和交互验收。
4. [技术执行计划](04-technical-execution-plan.md)：目标架构、数据与安全方案、实施波次和质量门禁。
5. [开发 Agent 任务清单](05-agent-backlog.md)：带依赖、文件范围和验收标准的可领取任务。
6. [测试运行手册](07-testing.md)：隔离数据库、安全守卫、fixtures 与自动化命令。

## 不可越过的边界

- 公司名称、Logo、域名、地址、电话、邮箱、营业时间、仓库面积、客户数、订单量、合作伙伴和公司历史尚未确定；开发 Agent 不得虚构或擅自替换占位内容。
- 保留 AGPL-3.0 许可证及 `LICENSE` 原文。
- 删除扫码对账全链路，不将其改造成新的仓库作业系统。
- 删除现有伪 2FA；本阶段不以另一个自制实现替代。
- “移除验证码放行”解释为：保留真实人机验证能力，删除客户端自证和缺少密钥时自动成功的 fail-open 路径。
- 未经新的明确授权，不执行 Git 提交、推送、重置或历史改写。
- `.codex-local/` 只保存本地对话记录，必须继续被忽略；正式规划文档应被版本管理，因此 `/docs` 不再忽略。

## 开发 Agent 使用方式

1. 先阅读全部五份文档，不从单个任务标题猜测范围。
2. 一次领取一个任务 ID，并在开始前声明将触碰的文件。
3. 遇到 `prisma/schema.prisma`、`prisma/migrations/0_init/migration.sql`、`package.json`、`src/config/site-config.ts` 或三份语言 JSON 时，按任务依赖串行处理，避免并行冲突。
4. 完成任务后执行该任务列出的局部校验；只有最终集成任务负责重新安装和全量门禁。
5. 不把“页面能打开”当作完成；服务端授权、错误状态、空状态、移动端、键盘操作和数据归属都属于验收范围。

## 决策优先级

若文档之间出现冲突，按以下顺序处理：用户最新明确要求 → `01-project-brief.md` → `04-technical-execution-plan.md` → `05-agent-backlog.md` → 其他说明。无法从代码或文档确定的公司事实必须保持占位并记录为待确认事项。
