## 不可越过的边界

- 公司法定/展示名称已确认为 `ZNB Logistics Inc.`，网站简称已确认为 `ZNB`。只允许 `BRAND-001` 按语义替换公开品牌；不得把客户填写的“公司名称”字段或内部测试标识一并全局替换。
- Logo、域名、地址、电话、邮箱、营业时间、仓库面积、客户数、订单量、合作伙伴、公司历史和可公开服务事实仍未确定；开发 Agent 不得虚构。
- 目标生产平台与套餐为 Vercel Hobby（项目方明确指定）。当前 `POST` 邮件 worker、单一 Prisma URL和 Hobby 无法高频运行 Cron 的限制，仍需由 `VERCEL-001` 改造成“Vercel Hobby + 外部邮件调度器”契约。
- Vercel 官方目前把 Hobby 限定为个人、非商业用途；技术方案按 Hobby 编写，但正式企业网站公开前必须由项目方确认使用资格或取得 Vercel 允许。文档不得把“技术可部署”写成“条款已满足”。
- 普通 Preview、固定 staging 和 Production 是三种不同信任边界；创建付费外部资源、写入平台 secret 或连接托管数据库必须由项目方 provision 或另行明确授权，领取开发任务本身不构成授权。
- 保留 AGPL-3.0 许可证及 `LICENSE` 原文。
- 删除扫码对账全链路，不将其改造成新的仓库作业系统。
- 删除现有伪 2FA；本阶段不以另一个自制实现替代。
- “移除验证码放行”解释为：保留真实人机验证能力，删除客户端自证和缺少密钥时自动成功的 fail-open 路径。
- 未经新的明确授权，不执行 Git 提交、推送、重置或历史改写。
- `.codex-local/` 只保存本地对话记录，必须继续被忽略；正式规划文档应被版本管理，因此 `/docs` 不再忽略。

## 开发 Agent 使用方式

1. 先阅读本导航、项目简报、技术计划、任务清单以及与任务相关的两份运行指南，不从单个任务标题猜测范围。
2. 一次领取一个任务 ID，并在开始前声明将触碰的文件。
3. 遇到 `prisma/schema.prisma`、`prisma/migrations/0_init/migration.sql`、`package.json`、`src/config/site-config.ts` 或三份语言 JSON 时，按任务依赖串行处理，避免并行冲突。
4. 完成任务后执行该任务列出的局部校验；新增发布波次由 `QA-004` 负责全量本地门禁和隔离 Preview 验收。
5. 不把“页面能打开”当作完成；服务端授权、错误状态、空状态、移动端、键盘操作和数据归属都属于验收范围。

## 决策优先级

若文档之间出现冲突，按以下顺序处理：用户最新明确要求 → `01-project-brief.md` → `04-technical-execution-plan.md` → `05-agent-backlog.md` → 其他说明。无法从代码或文档确定的公司事实必须保持占位并记录为待确认事项。
